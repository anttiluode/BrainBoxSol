Does noise-aware writing add to bridge repair?

Both proposed benefits failed. Under independent bridge drift, noise-aware writing increased target error by 4.3%. Combining it with interface repair left 3.34 times the error of repair alone.

The useful distinction: keeping a response stable and keeping it correct are separate goals. The combined arm slightly reduced change from its own trained response, but that response already had a larger clean error.

Primary comparison: independent drift, strength 0.6

Ten fresh simulated devices; 12 paired drift draws each. Mean absolute response error normalized by the initial device response. Lower is better; these are regression errors, not classification accuracies.

Interface repair reduced ordinary-writing error by 95.77%. Noise-aware writing improved on ordinary writing in only 1/10 devices; the combination improved on repair alone in 0/10.

Clean-fit cost

Ordinary: 3.814e-14. Noise-aware: 0.003825. The latter exceeds the predeclared 0.002 allowable penalty. Both writers used 48 updates, eight worlds, and identical forward/adjoint solve budgets.

What was learned

NCM-inspired conditioning corruption does not automatically confer robustness to a changed physical transfer operator. Here the noisy training bank introduced clean-fit bias and did not improve the primary held-out task. This does not rule out differently designed noise-aware methods. No learning settings were changed after the full source lock.

Protocol correction and limits

Development exposed that coherent interface drift is exactly canceled by interface-total repair. The primary was changed to independent per-edge drift before full devices were evaluated. V1 protocol and development receipts remain preserved. Coherent drift is retained as a mechanism check. This is a supervised six-port toy using global Gauss–Newton updates and stored interface set points; a six-value digital table would be cheaper.
